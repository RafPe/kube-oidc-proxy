# Prometheus metrics — TDD evidence

Evidence for the metrics endpoint, its versioned contract and its chart
surface, built across four phases (`metrics/phase-0-prep` through
`metrics/phase-3-chart-e2e`). Every RED and GREEN cell below comes from a real
run recorded while the change was built; no result here was written from
expectation. The per-phase working notes, with the full output each line was
taken from, are in `docs/superpowers/evidence/phase-{0,1,2,3}.md`.

## Journeys

- **An operator turns metrics on with one chart value and scrapes what the
  chart renders.** `metrics.enabled=true` renders the flag, a named container
  port and a dedicated ClusterIP Service `<release>-metrics` — never a port on
  the main Service, so `service.type=LoadBalancer` cannot expose it — plus an
  optional ServiceMonitor or PodMonitor, a PrometheusRule and a NetworkPolicy.
  The e2e suite derives the flag, the port name and the port from the *rendered
  chart* and deploys with exactly those, so a chart that drifts from the binary
  fails the suite rather than an operator's cluster.
- **An SRE reads request rate, denials by reason, open streams and p99 latency
  next to the API server's own.** Requests are observed in exactly one place,
  the `defer` of `withRequestLifecycle`, so a request is counted once and only
  once; watches are gauged as open streams and never enter the latency
  histogram; denials carry a closed-set `reason`.
- **A security reviewer proves no client-controlled string can become a
  label.** Every label value passes a projection onto a closed set inside
  `pkg/metrics` before it reaches a collector (unknown → `other`). Unit tests
  drive hostile input through the projections; the e2e suite sends 30 requests
  with invented methods, groups, resources and namespaces and then sweeps
  *every* label of *every* series for a `/` or an `@`.
- **A maintainer adds a metric and CI regenerates the docs.** A metric is one
  entry in the catalogue; `make metricdoc` regenerates the table in
  `docs/metrics.md` and `make verify_metricdoc` fails if it was not committed.
  Registering a collector that is not in the catalogue panics at construction.
- **A watch is counted as an open stream and never as a latency sample; an exec
  counts through its hijack.** Both are asserted at the recorder and through the
  real middleware chain. Against a live cluster only the watch is exercised: the
  e2e suite opens a watch, sees the gauge rise and fall and proves it was never
  timed. No `Metrics` spec performs an exec, so the hijack path has no e2e
  coverage — its evidence is the recorder and middleware-chain rows below.
- **Review API calls are counted where the API server is called, so coalesced
  and cached callers do not inflate them.** The counters sit at the single
  `Create` call site of each reviewer, not at the cache boundary.

## Not covered here

- TLS on the metrics listener and delegated authorization of scrapes are
  reserved: `metrics.tls.enabled` and `metrics.authentication.mode` fail the
  render at any value other than their default, which is asserted by
  `hack/verify-chart-metrics.sh` check 4 rather than by a behaviour test.
- The two `-race` failures inside `k8s.io/client-go/transport/cert_rotation.go`
  (`TestOIDCHTTPClientReloadsClientCertificate`,
  `TestRoundTripperForRestConfigReloadsClientCertificate`) are pre-existing on
  unmodified `main` and out of scope; every `-race` gate above runs with
  `-skip 'ReloadsClientCertificate'`, which excludes those two and nothing else.
